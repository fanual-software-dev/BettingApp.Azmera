# Owner dashboard

Deploy both Vercel frontend and Render backend. Startup creates `azmera.audience_join_dates` without resetting other tables. No new environment variables are needed. Access is limited to IDs in `PAYMENT_ADMIN_TELEGRAM_IDS`, enforced on `/api/admin/dashboard` as well as in the UI. Agents cannot access it.

Open Dashboard in the owner header. Agents see Payment review; Dashboard and Announcements remain owner-only. Wallet and Deposit are hidden for staff. Daily, Weekly, Monthly and Yearly select the current Gregorian calendar day, Monday-based week, month or year in Ethiopian time (UTC+3). Refresh reloads the figures. These are calendar-to-date periods, not rolling 24-hour/7-day/30-day windows.

New-user counts combine registered Telegram users and tracked bot visitors, deduplicated by Telegram ID. Existing registration consent dates backfill join dates. Older bot visitors retain unknown dates and are added as a baseline to every Users Joined count as requested by the owner. These adjusted totals are not strict new joins within each period. Payment counts are unaffected. A new user's first private bot interaction or registration establishes their date; subsequent starts and logins do not reset it. These are recorded joins, not Telegram's monthly-active-user metric. Visitors from before bot tracking was enabled cannot be recovered automatically.

Payment cards count requests created in the selected period, grouped by their current status (not the time of approval). Completed includes approved deposits and paid withdrawals. Pending includes drafts, pending requests and processing withdrawals. Canceled includes cancelled, rejected and failed requests. All three groups add up to the total request count. These are counts, not sums of money.

The user list includes bot-only visitors and registered users, with search by name, phone or Telegram ID and pages of 10. Missing phone numbers display “Phone not shared.” Total wager is a lifetime sum of stakes across sandbox rounds and stored Aviator/Chicken Road bets, excluding refunded bets. It includes open bets and does not subtract payouts. Current provider adapters and the wallet use sandbox/test credits, so the dashboard explicitly labels this as test wagering rather than real-money turnover. Games without stored bets contribute zero; no wagers are invented for unconnected games.

Tests cover UTC+3 boundaries, Monday/year/leap-month periods, audience deduplication, unknown dates, repeated starts, status mapping, refund exclusions, search, and owner-only HTTP access. No production data is modified by tests.
